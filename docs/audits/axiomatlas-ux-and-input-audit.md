# AxiomAtlas Complete Calculator Input & Mathematical UX Audit

**Live Website:** [AxiomAtlas](https://axiomatlas.netlify.app/)
**Audit Scope:** Section 3 — Trigonometric Input Improvements, Reusable Mathematical Input Architecture, Calculator-Specific Input Audit (all 136 calculators), and Units & Notation Standardization.
**Status:** Phase 0 Audit Deliverable — Zero production code or UI changes made.

## 1. Executive Diagnosis reveals syntax barriers and missing unit selectors across 7 expression tools and 113 formula tools

Source-code inspection of `site/assets/engine.js` (lines 2–16) and `site/assets/app.js` (lines 54–84) reveals two distinct UX regimes across the 136 calculators:
1. **7 Expression-Parsing Calculators (`scientific-calculator`, `equation-solver`, `expression-simplifier`, `graphing-calculator`, `derivative-calculator`, `integral-calculator`, `limit-calculator`):** Force users to type raw ASCII parser strings (`asin(x)`, `sin(x)^2`, `sqrt(x)`, `2*x^3`) into plain `<input type="text">` fields (`site/assets/app.js` lines 55–65) with **no live mathematical preview**, **no contextual keypad** (on 6 of the 7 tools), and **strict parser pitfalls** (e.g., typing `√9` throws `Unknown variable: sqrt9`; typing `x(x+1)` throws `Unknown function: x`; typing `sin^2(x)` throws `Unexpected token: ^`).
2. **113 Formula Calculators + 16 Structured Specialized Calculators:** Use plain numeric inputs (`<input type="number" step="any">`), but suffer from **static, non-interactive unit pills** (e.g., `m`, `kg`, `s` hardcoded in `source/make_catalog.py`, with 43 formula calculators lacking unit pills altogether), **one-way formula evaluation** (users cannot enter Hypotenuse $c$ and Leg $a$ to solve for Leg $b$ in `pythagorean-calculator`), **hardcoded input counts** (e.g., 4 numbers in `arithmetic-mean`, 3 numbers in `geometric-mean`, 3 pairs in `weighted-average`, 3 resistors in `resistor-series`/`resistor-parallel`), and **missing domain validations on 69 formula calculators**.

### 2.2 Mandatory Semantic & UI Disambiguation Rules for AxiomAtlas 2.0

AxiomAtlas must **never** interchange the four distinct trigonometric constructs below. Both the parser (`engine.js`), the keypad (`app.js`), and the live math preview bar must enforce and visually distinguish them:

| Construct | Mathematical Meaning | Canonical AST Representation | Accepted User Input Aliases (Parser Upgrade) | Keypad Button Label & Tooltip | Live Math Preview Rendering |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Direct Ratio** | Sine of angle $x$ | `['call', 'sin', [x]]` | `sin(x)` | `sin` — *Sine of angle: sin(x)* | $\sin(x)$ |
| **2. Inverse Function** | Angle whose sine is $x$ ($rcsin x$, domain $[-1, 1]$) | `['call', 'asin', [x]]` | `asin(x)`, `arcsin(x)`, `sin⁻¹(x)` | `sin⁻¹` (under `2nd / inv` shift or dedicated row) — *Inverse sine (arcsin): returns angle whose sine is x* | $\sin^{-1}(x) 	ext{ [arcsin]}$ |
| **3. Reciprocal Ratio** | Cosecant of angle $x$ ($rac{1}{\sin x}$, where $\sin x 
eq 0$) | `['call', 'csc', [x]]` | `csc(x)`, `cosec(x)`, `1/sin(x)` | `csc` (`1/sin`) — *Reciprocal of sine: csc(x) = 1 / sin(x)* | $\csc(x) = rac{1}{\sin(x)}$ |
| **4. Squared Function** | $(\sin(x))^2 = \sin(x) 	imes \sin(x)$ | `['op', '^', ['call', 'sin', [x]], ['n', 2]]` | `sin(x)^2`, `(sin(x))^2`, `sin^2(x)`, `sin²(x)` | `sin²(x)` template chip or `x²` applied after `sin(x)` — *Sine squared: (sin(x))²* | $(\sin(x))^2$ |
| **5. Function of Squared Input** | Sine of $(x^2)$ | `['call', 'sin', [['op', '^', x, ['n', 2]]]]` | `sin(x^2)`, `sin(x²)` | `sin(` followed by `x²` inside parentheses — *Sine of x-squared: sin(x²)* | $\sin(x^2)$ |

**Recommended UI Controls to Eliminate Trigonometric Confusion:**
1. **Explicit "Live Interpretation Preview" Bar:** Immediately below any expression input field, render a human-readable mathematical preview (e.g., when a user types `sin(x)^2`, display: `Interpreted as: (sin(x))² — Sine of x, squared`; when a user types `asin(0.5)`, display: `Interpreted as: arcsin(0.5) — Inverse sine [returns angle in ° or rad]`).
2. **Contextual Ambiguity Guard:** If a user types `sin^-1(x)` into an expression box, do **not** silently evaluate it as `1/sin(x)` or throw a syntax error. Instead, auto-convert or show a 1-click disambiguation chip: *"Did you mean `arcsin(x)` (inverse sine, $\sin^{-1}x$) or `1/sin(x)` (reciprocal cosecant, $\csc x$)?"*
3. **Complete `Trigonometry Calculator` (`/tools/trigonometry-calculator/`) Modes:** Upgrade `trigonometry-calculator` with two clear tabs:
   - **Tab 1 — Forward Trig Ratios (Given Angle $	heta$):** Computes all 6 ratios (`sin θ`, `cos θ`, `tan θ`, `cot θ`, `sec θ`, `csc θ`) with exact reference values (e.g., $rac{1}{2}, rac{\sqrt{3}}{2}$) alongside decimal approximations, and snaps exact multiples of $90^\circ / \pi$ to $0$ or `Undefined`.
   - **Tab 2 — Inverse Trig Functions (Given Ratio $x$):** Computes `arcsin(x)` ($\sin^{-1} x$), `arccos(x)` ($\cos^{-1} x$), `arctan(x)` ($	an^{-1} x$), `arccot(x)`, `arcsec(x)`, and `arccsc(x)` in both Degrees and Radians with explicit principal-domain explanations (e.g., $|x| \le 1$ for $rcsin, rccos$).

### 3.2 Three-Tier Input Assignment Strategy (Preventing Unnecessary Complexity)

Per the requirement *"Do not make simple calculators unnecessarily complicated"*, AxiomAtlas must **not** put a visual equation editor on simple numeric calculators like `bmi-calculator` or `emi-calculator`. Instead, every calculator is assigned to one of three precise UX tiers:

- **Tier 1 — Full Mathematical Expression Bar + Live Preview + Collapsible Math Keypad (7 Calculators):**
  - `scientific-calculator`, `equation-solver`, `expression-simplifier`, `graphing-calculator`, `derivative-calculator`, `integral-calculator`, `limit-calculator`.
- **Tier 2 — Structured Interactive Grid / Multi-Row / Multi-Format Input (18 Calculators):**
  - **2D Matrix Grids (2):** `matrix-calculator`, `linear-system` (upgrade to preserve entries on resize, add 4×4 option, and render 2D bracketed output).
  - **Dataset / Dynamic Row Inputs (7):** `statistics-calculator`, `correlation-calculator`, `weighted-average`, `arithmetic-mean`, `geometric-mean`, `resistor-series`, `resistor-parallel` (upgrade fixed 3/4-input forms to dynamic `+ Add row` / comma-separated list inputs).
  - **Specialized Format Inputs (9):** `fraction-calculator` (add mixed-number fields), `number-base-converter` (bases 2–36 selector), `color-converter` (add editable HEX/RGB/HSL text fields), `unit-converter`, `trigonometry-calculator`, `vector-calculator`, `date-difference`, `age-calculator`, `random-number-generator`.
- **Tier 3 — Clean Numeric Inputs with Interactive Unit Selectors & "Solve-For" Mode Toggles (111 Calculators):**
  - All remaining Geometry, Physics, Finance, Statistics, Education, Computing, and Everyday formula calculators keep fast `<input type="number" step="any" inputmode="decimal">` controls, upgraded with **interactive unit dropdown pills** and **domain-specific validation**.

## 5. Units, Dimensional Analysis, and Notation Standardization (Section 3.4)

### 5.1 Current Unit & Formatting Architecture Audit

1. **Disjoint Unit Systems:** `site/assets/engine.js` (lines 24–40) already contains a rich `unitGroups` dictionary covering **16 physical dimensions and 103 units** (`Length`, `Mass`, `Area`, `Volume`, `Speed`, `Time`, `Temperature`, `Pressure`, `Energy`, `Power`, `Data`, `Angle`, `Frequency`, `Force`, `Density`, `Torque`), yet **only 1 calculator (`unit-converter`) uses `unitGroups`!** All 113 formula calculators merely render a static `<span class="unit-pill">` string (`site/assets/app.js` line 54).
2. **Broken Small-Number Clamping in `engine.js`:** Line 15 of `site/assets/engine.js` executes:
   ```javascript
   return Math.abs(v) < 1e-13 ? 0 : v;
   ```
   This blanket threshold destroys every calculation whose true answer has magnitude $< 10^{-13}$ (such as `gravitational-force` where $G = 6.6743 	imes 10^{-11}$, atomic/quantum scales, small probabilities, and negative powers like $10^{-14}$), even though `fmt(v)` on line 17 was specifically written to format values $< 10^{-6}$ in scientific notation (`v.toExponential(7)`)!
3. **Number Formatting (`fmt(v)` in `site/assets/engine.js` line 17):**
   ```javascript
   export function fmt(v){
     if(typeof v==='string')return v;
     if(!Number.isFinite(v))return 'Undefined';
     if(Object.is(v,-0))return '0';
     if(Math.abs(v)>0 && (Math.abs(v)<1e-6 || Math.abs(v)>=1e12))
       return v.toExponential(7).replace('e+','e');
     return new Intl.NumberFormat('en-US',{maximumFractionDigits:9}).format(Number(v.toPrecision(12)));
   }
   ```
   While `fmt(v)` handles `0`, `-0`, `1e-6..1e12` (12 significant figures, max 9 decimal places), and scientific notation cleanly, the raw `data-copy` attribute on the copy button (`site/assets/app.js` line 23) copies unformatted IEEE-754 floats (e.g., `0.30000000000000004` instead of `0.3`).

### 5.2 Recommended Application-Wide Unit & Notation Conventions

1. **Replace Static `.unit-pill` with Interactive Unit Selectors Linked to `unitGroups`:**
   - Extend `catalog.json` field schema with an optional `unitGroup` property (e.g., `unit: "m", unitGroup: "Length"`).
   - When `f.unitGroup` is present (or inferred from `f.unit`, e.g., `m` → `Length`, `kg` → `Mass`, `s` → `Time`, `N` → `Force`, `Pa` → `Pressure`, `J` → `Energy`, `W` → `Power`, `Hz` → `Frequency`, `°` → `Angle`), `form()` in `site/assets/app.js` renders a compact `<select class="unit-pill-select">` defaulting to the catalog's canonical SI unit.
   - Before calling `calculate(o.expr, v)`, each input value is converted from the user's selected unit to the formula's canonical SI unit via `convertUnit(group, rawVal, selectedUnit, canonicalUnit)`. Output lines with a matching `unitGroup` allow 1-click unit switching on the result card as well!
2. **Fix Near-Zero Snapping vs. Scientific Notation:**
   - **Remove** `Math.abs(v) < 1e-13 ? 0 : v` from `run()` in `site/assets/engine.js`!
   - Instead, apply targeted floating-point cancellation snapping **only** inside trigonometric evaluation (`sin`, `cos`, `tan`) when an angle is within $10^{-15}$ of a multiple of $\pi/2$:
     - If $|\sin(	heta)| < 10^{-15}$, return `0`.
     - If $|\cos(	heta)| < 10^{-15}$, return `0` (and for `tan`/`sec`, throw `DomainError('Undefined at vertical asymptote')`).
   - This preserves `sin(pi) = 0` and `cos(90°) = 0` while allowing `gravitational-force` ($6.6743 	imes 10^{-15}	ext{ N}$) and `10^-14` to evaluate and display accurately as `6.6743000e-15 N` and `1.0000000e-14`!
3. **Standardize Scientific Notation & Significant Figures Display:**
   - Format scientific notation in the UI as human-readable `$6.6743 	imes 10^{-15}$` (with `6.6743e-15` copied on click for spreadsheet/code compatibility).
   - Add an optional global or per-card **Precision Toggle** (`Auto (12 sig figs)` / `2 decimals` / `4 decimals` / `6 decimals` / `Scientific`).
